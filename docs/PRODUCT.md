# Product — Digital Behaviour Intelligence

## Problem

Product teams see raw event firehoses (views, taps, sessions) but not **who is warming up, cooling off, or shifting pattern** — or why.

## Solution (Option 4 pipeline)

One intelligence system:

**events → profiles → segments → change → engagement forecast → priority queue with explanations**

## Use cases (YES)

- Product / growth: find Declining users early with feature-level reasons
- Ops: prioritise outreach or experiment cohorts by segment + trajectory
- Interview / portfolio: prove event-level Pandas/NumPy/sklearn end-to-end
- Case study framing: Instagram-style **product usage** behaviour

## Non-use (NO)

- **Not** an addiction / clinical / mental-health predictor
- **Not** a content recommender or ranking engine
- **Not** four disconnected ML homework scripts
- **Not** a production multi-tenant SaaS (yet)
- **Not** “one row per user already aggregated” as the only input (kills the event→profile story)

## Success

You can ingest event logs, build user features, show clusters, flag change, predict Increasing/Stable/Declining, and open a simple dashboard / report for a chosen user with explanations.
